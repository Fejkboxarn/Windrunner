# Production-only and Character Tuning acceptance

This is a new acceptance pass. The earlier report of 8/11 RC3 areas passing does not certify these ownership/configuration changes. Use a copy of the scene for character variants; do not save experimental runtime edits into Batch1_Playground. Defaults remain numerically unchanged, but animation ownership is deliberately different.

1. **Open the Studio and check the installed character.** Open Batch1_Playground, select Airflow Player, Tools > Windrunner > Character Tuning, Use selected player. Click Validate and Production-only audit. Expect no errors, named module assets and the same authored values as before. The production character should contain no retired pose writers/input repair/quarantined overlays and no player Animator controller. Missing source/profile references or duplicate authorities are failures. No special setup.
2. **Production-only gameplay.** Enter Play without pressing any migration/start-animation menu. Click Production-only audit: portable ownership must already be active. Test walk/run/reversal/jump/fall/land, manual/reward Dash, normal/perfect/canceled Sling/Cast, water entry/exit and pause/hit-stop. Compare movement and ability feel to accepted RC3. Missing Cast/Dash/start clips should keep a valid portable pose, never enable a legacy component. Visual clipping/foot sliding/placeholder blends must be recorded for acceptance even if gameplay is correct.
3. **Lifecycle/failure visibility.** In Play, disable/re-enable AirflowPortableAnimationBridge or use the existing acceptance Stop/Start commands. Stop intentionally leaves no active pose graph; it must not revive a legacy Animator. Re-enable restores automatic portable ownership. Reload twice and audit again. Duplicated pose writers, stale listeners, root-motion displacement or silent legacy fallback are failures. Tests exercise this automatically too; visual transitions remain manual.
4. **Safe live tuning.** In Play select/load the running player in the Studio and enable Live preview. Change maxGroundSpeed by a small amount, run, and compare. Try a jump height or Sling/Cast timing change when idle, not mid-traversal. Expect immediate supported-profile changes; compare changed values against baseline and Revert. Close/reopen or disable preview: bindings must restore original assets. Stop Play without Save: no authored value should persist. Cached animation/audio/feedback changes are restart-only and explicitly labeled.
5. **Explicit persistence, Undo and conflict handling.** On an independent variant profile set, change a value and click Save changes to assets. Stop/start Play and confirm it persists. Undo/Redo uses Unity's standard Edit menu; after undoing an authored save, reload the Studio snapshot before further saving and use Save Project to persist the undone asset. An external asset edit while a draft is open should reject stale Save, not overwrite it. Invalid ranges/missing animation configuration should block Save and stop live preview. Automated tests cover draft isolation, no-op saving, actual save and Undo on disposable data.
6. **Future character preset.** Stop Play; load Petra and choose Duplicate character profiles with a new name. This creates independent logical module assets and a preset, without copying gameplay C#. Use a separately prepared production character with matching relative component paths and its own camera/rig composition; apply the new preset in Edit Mode, then save that variant scene/prefab deliberately. Test one local playable character at a time; this is not a multiplayer bootstrap feature. The original Petra assets must not change. Mismatched paths/types must be reported, not guessed. Configure a new Humanoid Avatar/rig as composition work before tuning; the Studio is not a mesh importer or automatic rig authoring tool.
7. **Animation and feedback content.** In the Studio's Animation category, inspect clip/action mappings and blending values; use a variant before changing clips. Save/restart to test graph changes. Verify jump/landing, flip and Sling phases, masks/interruption, FEEL/audio/UI and waterfall near/far attenuation. No missing clip may trigger hidden legacy playback. The existing waterfall fix remains in the new build.
8. **Performance and Editor workflow.** Use representative rendered traversal and repeated reloads on the target hardware. Check Studio responsiveness with category/search filtering and that closing it ends live preview. Capture CPU/GC/GPU where supported; compare identical routes/settings. Existing automated Editor measurements include test overhead and do not certify shipping frame budgets. Windows startup only proves initialization, not these interactive checks.

Record each item as not tested/pass/fail with checkpoint, scene, device, action sequence and Console output. No item in this guide is automatically marked passed by compilation.
